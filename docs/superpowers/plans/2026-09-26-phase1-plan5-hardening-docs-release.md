# Phase 1 · Plan 5 — Hardening, documentation and release pipeline

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or superpowers:subagent-driven-development) to implement this plan task by task.

**Goal:** Close every open item left by Phase 1 plan 4. Give the project the documentation and release machinery of a maintained open project:
- a README;
- user and technical documentation;
- contributor and agent guides;
- Conventional Commits, SemVer, release-please, and per-platform release binaries.

**Architecture:** No new crates. Code changes are limited to the Phase 1 plan 4 review minors and one model rule. Everything else is Markdown, YAML and TOML.

**Spec:** `docs/superpowers/specs/2026-09-25-fauste-player-design.md` (§3 rules, §6 formats, §8, §9, §11, §13).

## Global Constraints

- Everything is in English: code, docs, commit messages.
- Never mention third-party radio-automation products.
- Follow established conventions and do not invent names. The references are:
  - Conventional Commits 1.0.0;
  - Semantic Versioning 2.0.0;
  - Keep a Changelog layout, as generated by release-please;
  - the `release-please-action` v4 manifest configuration.
- No hardcoded product limits. Lints stay as they are: `forbid(unsafe_code)`, and no unwrap, expect or panic outside tests.

## Review Focus

1. **Release PR builds after a version bump.** release-please bumps the version but not `Cargo.lock`, so a `--locked` build must still work. The release config updates the workspace crate versions in both `Cargo.toml` and `Cargo.lock`.
2. **Release artefacts per OS.** A tag must yield one downloadable archive per target, each with a checksum:
   - `x86_64-unknown-linux-gnu`;
   - `aarch64-unknown-linux-gnu`;
   - `x86_64-pc-windows-msvc`;
   - `x86_64-apple-darwin`;
   - `aarch64-apple-darwin`.
3. **The two agent guides.** CLAUDE.md and AGENTS.md must not diverge: one is canonical and the other links to it.
4. **Test hooks.** A release binary must not contain the panic-injection hook.
5. **Duplicate on-air entries.** Two idle players must not both derive the same entry as next while it is on air elsewhere.

### Task 1: Plan 4 review minors and the duplicate-next rule

- **M1:** the fader and the Settings sliders send a command only when the value changed.
  - Done as part of C2 for the fader.
  - For sliders: `update()` compares the new value with the config before sending (already true).
- **M2:** move `AppUi::fail_next_frame` behind a cargo feature `test-hooks`.
  - The integration tests enable it through `[dev-dependencies] fp-app = { path = ".", features = ["test-hooks"] }`.
  - Test: `release builds have no test hooks` is a compile-level guarantee, checked by building with `--no-default-features`.
- **M3:** make `AUDIO_EXTENSIONS` match spec §6: WAV, AIFF, FLAC, MP3, OGG Vorbis, AAC/M4A, ALAC.
  - Remove `opus`, `mkv`, `webm`, `mp4`, `mka`.
  - Test: `opus_and_video_files_are_not_accepted`.
- **M4:** the services thread wraps each `step` in `catch_unwind`, logs the panic, keeps running, and increments a `faults` counter that the UI shows as a status-bar alert.
  - Test: `a_panicking_step_does_not_stop_autosave`, with an analyzer result routing that panics via an injected hook behind `test-hooks`.
- **M5:** pressing Esc while renaming a playlist restores the old name.
  - Test (kittest): `escape_cancels_a_playlist_rename`.
- **M6:** the test tone.
  - The conductor handles at most one tone request per tick (rendering 1.5 s takes well under 1 ms, so no helper thread).
  - Release the slot if `Start` fails after `Attach`.
  - Test: `a_failed_tone_start_releases_the_slot` (Offline).
- **M7:** expand dropped folders on a helper thread. Results arrive through the same channel as file-dialog picks.
- **M8:** the remaining visible strings go through Fluent. `error-other` carries the error kind, not English text.
  - New keys: `placeholder-none` (—), `unit-hz`, `volume-silent` (−∞ dB).
  - Test: `both_locales_define_the_same_keys` still passes.
- **M9:** `demo_session` refuses to run without `FAUSTE_HOME`.
- **M10:** `row_status` takes the `PlaylistEntry` directly.
- **Duplicate next (new rule 21 in the spec):** a derived next (not explicit), and the pick of an idle player, skips entries that are on air (current) on another player.
  - Tests (fp-model): `an_idle_player_does_not_pick_an_entry_on_air_elsewhere` and `derived_next_skips_entries_on_air_elsewhere`.

### Task 2: Conventional Commits, SemVer and release-please

- **`release-please-config.json`:**
  - release type `simple`;
  - `include-component-in-tag: false`;
  - `bump-minor-pre-major: true`;
  - changelog sections: feat, fix, perf, refactor, docs, and so on;
  - `extra-files`: TOML updaters for `Cargo.toml` `$.workspace.package.version` and for each workspace crate in `Cargo.lock`.
- **`.release-please-manifest.json`:** `{ ".": "0.1.0" }`.
- **`CHANGELOG.md`:** a seed with an "Unreleased" note; release-please owns it from then on.
- **`.github/workflows/release-please.yml`:** runs on push to master.
- **`.github/workflows/release.yml`:**
  - runs when a release is published, or on `workflow_dispatch` with a tag;
  - build matrix over the five targets;
  - produces `fauste-player-<version>-<target>.tar.gz`, or `.zip` on Windows;
  - each archive holds the binary, the README, the licence notices and the fonts licence;
  - each archive has a `.sha256` file;
  - uploads to the GitHub release with `gh release upload`.
- **`.github/workflows/commits.yml`:**
  - checks PR titles with `amannn/action-semantic-pull-request`;
  - checks the PR's commit subjects against the Conventional Commits types with a small shell step.
- **`.github/pull_request_template.md`** and **`.github/ISSUE_TEMPLATE/`** (bug report, feature request).
- **Validation:** `actionlint` if available, and a Python YAML parse otherwise; `jq` on the JSON files.
