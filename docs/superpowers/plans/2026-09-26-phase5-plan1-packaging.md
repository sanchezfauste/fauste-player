# Phase 5 · Plan 1 — Packaging

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or superpowers:subagent-driven-development) to implement this plan task by task.

**Goal:** Installable packages for every platform, built by CI on each release and attached to it next to the archives:
- Linux: `.deb`, `.rpm`, AppImage, and a Flatpak manifest;
- Windows: an MSI;
- macOS: an `.app` in a `.dmg`.

Signing and notarisation run when their secrets are configured, and are skipped (with a note in the release) otherwise.

**Architecture:**
- **Shared application metadata** in `packaging/`:
  - an application id: `org.fauste.FaustePlayer`, reverse-DNS as Flatpak and AppStream require;
  - an SVG icon plus rendered PNG sizes;
  - a `.desktop` file;
  - AppStream `metainfo.xml`;
  - macOS `Info.plist` and `.icns`;
  - Windows `.ico` and WiX sources.
- **One script per format** in `scripts/package/`, runnable locally and in CI.
- **The `release-build` workflow** gains a `packages` job per OS, run after the archives.

**Spec:** parent spec §13 (Phase 5: deb, rpm, Flatpak, AppImage; signed MSI; signed and notarised dmg). Exit criterion: installable artefacts produced by CI.

## Global Constraints

- **Rules carried over:** English; no third-party product names; licences respected (the fonts' OFL and `THIRD-PARTY.html` go into every package); SemVer version from `Cargo.toml`.
- **Runtime dependencies:**
  - Every package ships the binary the release archives ship. It is built with `jack` (loaded at run time), without `pipewire` (Phase 3 ruling: libpipewire would become a start-up dependency). So it links only ALSA, D-Bus and the C runtime, and `scripts/check-runtime-deps.sh` guards that.
  - Linux packages declare those libraries (`$auto` in cargo-deb, the same list in rpm), and recommend `pipewire-pulse | pulseaudio`.
  - The AppImage bundles nothing beyond the binary and its resources, since ALSA and D-Bus are present on every desktop.
  - The Flatpak uses the freedesktop runtime.
- **No secrets in the repository.** Signing uses GitHub secrets: `WINDOWS_CERT_PFX`, `WINDOWS_CERT_PASSWORD`, `APPLE_CERT_P12`, `APPLE_CERT_PASSWORD`, `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_PASSWORD`. Every signing step is skipped cleanly when its secrets are absent.

## Review Focus

1. **A `.deb` installed on a clean Debian or Ubuntu** that lacks the optional audio libraries. The package must declare what the binary needs, so it either pulls those libraries in or the binary still starts.
2. **The AppImage on a minimal distribution** (no JACK, no PulseAudio server). It starts, and plays through ALSA; JACK and PulseAudio show as unavailable.
3. **An unsigned MSI or dmg.** The release notes say how to get past SmartScreen and Gatekeeper.
4. **The package version** matches the release tag, and upgrades replace the older version (same MSI UpgradeCode, same deb package name).
5. **The desktop integration:** the icon, the menu entry with its name and categories (`AudioVideo;Audio;`), and the file associations for playlists (`audio/x-mpegurl`, `audio/x-scpls`).

### Task 1: Application metadata and icon

- `packaging/icon.svg`: a broadcast glyph on the Nocturne accent, square.
  - PNG sizes 16–512 rendered with `rsvg-convert` or ImageMagick.
  - `.ico` and `.icns` built from them.
- `packaging/linux/org.fauste.FaustePlayer.desktop`: Exec, Icon, Categories, and MimeType for M3U/PLS.
- `packaging/linux/org.fauste.FaustePlayer.metainfo.xml`: AppStream, validated with `appstreamcli validate`.
- `fauste-player <playlist file>` imports that file as a new playlist at start-up, so a file association opens it.
  - Test: `a_playlist_path_argument_is_imported_at_start`.
- The window icon is set from the PNG in eframe's `ViewportBuilder::with_icon`.

### Task 2: Linux packages

- `.deb` through `cargo-deb` metadata in `crates/fp-app/Cargo.toml`:
  - assets: the binary, the desktop file, the metainfo, the icons, the licences;
  - `depends` auto-detected (`$auto`).
- `.rpm` through `cargo-generate-rpm` metadata, with the same assets.
- AppImage through `scripts/package/appimage.sh`:
  - build an AppDir (binary, `.desktop`, icon, `AppRun`);
  - package it with `appimagetool`;
  - run a smoke test with `--appimage-extract-and-run --version`.
- Flatpak: the manifest `packaging/flatpak/org.fauste.FaustePlayer.yml`:
  - freedesktop runtime 24.08;
  - rust-stable SDK extension;
  - offline cargo sources generated by `flatpak-cargo-generator`;
  - permissions for PulseAudio/PipeWire sockets, the home folder read-only for music (portal file dialogs for everything else), and X11/Wayland.

  CI builds it with `flatpak-builder` and uploads a `.flatpak` bundle.
- Local verification, where the tools exist: build the `.deb` and inspect it with `dpkg-deb -c`, build the `.rpm`, and build the AppImage.
- `fauste-player --version` prints the version, for package smoke tests.

### Task 3: Windows MSI

- `cargo-wix` with `packaging/windows/main.wxs`:
  - per-machine install;
  - Start menu shortcut;
  - a fixed UpgradeCode so upgrades replace the older version;
  - the licence page;
  - icon.
- Signing with `signtool` when `WINDOWS_CERT_PFX` is set.

### Task 4: macOS app and dmg

- `scripts/package/macos.sh`:
  - build `Fauste Player.app`: `Info.plist` with the bundle id `org.fauste.FaustePlayer`, the version, the icon, `NSMicrophoneUsageDescription` not needed, and `LSMinimumSystemVersion`;
  - build a universal binary with `lipo` from the two targets;
  - create the dmg with `hdiutil`.
- Signing (`codesign --options runtime`) and notarisation (`notarytool submit --wait`, then `stapler`) run when the Apple secrets are set.

### Task 5: Release workflow and docs

- `release-build.yml` gains packaging jobs after the archives:
  - `linux-packages`: deb, rpm, AppImage for x86_64 and aarch64; Flatpak for x86_64;
  - `windows-msi`;
  - `macos-dmg`.

  Each package has a `.sha256` and is uploaded to the release.
- **Docs:**
  - README install per format;
  - `docs/user/getting-started.md`, with installing, updating and uninstalling per format;
  - `docs/technical/release-process.md`, with the packaging jobs and the signing secrets.
- **Verification:** actionlint, local package builds where possible, a fresh review, fixes, then merge.
