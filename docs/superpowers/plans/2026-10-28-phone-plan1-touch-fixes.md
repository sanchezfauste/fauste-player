# Phone plan 1 — touch fixes, licences in the APK, closing the app

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** faders and waveforms that work by touch, the third-party notices
inside the APK, and an app that ends when it is closed with nothing on air.

**Architecture:** UI changes in `fp-app/src/ui` (fader enablement, waveform
click position, pinch input); the notices are generated by `android.sh` into
the APK's assets and copied out by the activity; Back is routed to Rust,
which goes back inside the interface or asks the activity to close (end the
process after the services' final save) or to move to the background.

**Tech Stack:** Rust, egui/eframe 0.37, egui_kittest, Kotlin (GameActivity,
FileProvider), cargo-about.

**Spec:** `docs/superpowers/specs/2026-10-28-phone-layout-design.md`
(PL2 in part, PL14–PL16, PL22–PL24).

## Global Constraints

- `unsafe` only in `fp-mobile` entry points and JNI calls, each with `#[allow(unsafe_code)]` and `// SAFETY:`.
- No `unwrap`/`expect`/`panic` outside tests; the UI never blocks on I/O.
- Nothing goes on air by itself after a start (rule 10).
- New strings in all 11 locales (none expected in this plan).
- Tablet and desktop behaviour unchanged except PL14–PL16, which apply to touch everywhere.

## Review Focus

- A finger scroll that *starts beside* a fader must never send `SetVolume` (test in Task 1).
- A tap on a waveform in a scrolling area seeks once, at the tap, and a drag on it sends no seek (Task 2).
- A pinch whose fingers are outside the waveform must not zoom it (Task 3).
- Back with a window open closes the window, never the app (Task 5).
- Back or close with a cart or a CUE pre-listen playing keeps the process (Task 5: `playout_active` covers carts and CUE).

### Task 5: Back and closing the app (PL2 in part, PL23, PL24)

**Files:** Modify `crates/fp-app/src/ui/app.rs` (`AppUi::back`), `crates/fp-app/src/platform.rs` (`Platform::leave`), `crates/fp-app/src/session.rs` + `services.rs` (`AppSession::stop_services(&self)`), `crates/fp-mobile/src/{jni.rs,android.rs,platform.rs}`, `MainActivity.kt`, `Native.kt`, `PlaybackService.kt`; Test `crates/fp-app/tests/it/touch_ui.rs`, `crates/fp-app/tests/it/services.rs` (or `session` tests).

**Interfaces:**
- `AppUi::back(&mut self, ctx: &egui::Context) -> bool` — goes back one step inside the interface; `false` when there is nothing to go back to. Order: an open media browser is cancelled; then the Settings window; then About; then a phone's open player (`phone.open = None`). (Later plans add their screens.)
- `Platform::leave(&self, playing: bool)` — default no-op; Android: `playing` → move the task to the background, otherwise close (Kotlin `closeApp()`).
- `AppSession::stop_services(&self)` — stops the services thread after its final save (idempotent; `ServicesHandle` keeps its thread in a `Mutex<Option<JoinHandle<()>>>`).
- JNI: `Native.back()` (Kotlin → Rust: sets an `AtomicBool` and requests a repaint through the stored `egui::Context`), `Native.quit()` (Rust `SESSION.get().map(AppSession::stop_services)`), Kotlin `MainActivity.leave(close: Boolean)` called from Rust.

- [ ] Tests: `back_closes_settings_before_anything_else`, `back_closes_an_open_player`, `back_with_nothing_open_reports_nothing_to_go_back_to` (kittest on `AppUi`); `stop_services_saves_and_is_idempotent` (state saved to the store after a change, a second call returns at once).
- [ ] Run: they fail (no such methods).
- [ ] Implement `AppUi::back`, `stop_services`, and in `MobileApp::update` take the back flag: `if !shell.back(ctx) { platform.leave(fp_model::playout_active(&state)) }`.
- [ ] Kotlin: Back key and back gesture call `Native.back()` instead of `moveTaskToBack`. `leave(close)`: `close == false` → `moveTaskToBack(true)`; `true` → on a background thread `Native.quit()`, then on the UI thread `finishAndRemoveTask()` and `Process.killProcess(Process.myPid())`. `PlaybackService`, stopping itself because playout ended while no activity is alive (`MainActivity` not resumed nor started — track with a companion flag set in `onStart`/`onStop`), does the same quit and kill.
- [ ] Emulator checks (record in the ledger): nothing playing + Back → the process is gone (`adb shell pidof com.sanchezfauste.FaustePlayer` empty) and the next launch shows the saved playlists; playing + Back → keeps playing with the notification; playing + swipe from recents → keeps playing; nothing playing + swipe → process gone; Settings open + Back → Settings closes.
- [ ] Commit `feat(mobile): close the app with Back when nothing plays`.
